# S3-compatible storage drive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an S3-compatible `StorageDrive` (AWS S3, Backblaze B2, MinIO, R2, ...) selectable next to SMB / WebDAV / NFS, with an app form, background-sync support and MinIO-backed tests.

**Architecture:** New Go package `server/drive/s3` implements `imgmanager.StorageDrive` on top of `minio-go` v7. A new `SetDriveS3` gRPC RPC validates then activates it. The Flutter app gets `Drive.s3`, an `S3Form`, prefs keys and an `initDrive()` case (which background sync already reuses). Layout, thumbnails and encryption stay in `ImgManager`, unchanged.

**Tech Stack:** Go 1.25+ (`github.com/minio/minio-go/v7`), protobuf/gRPC, Flutter 3.41.4 / Dart 3.11.1, Docker (MinIO) for tests.

**Spec:** `docs/superpowers/specs/2026-11-19-s3-drive-design.md`

## Global Constraints

- Client library is `minio-go` v7 (not aws-sdk-go-v2). No listing cache or thumbnail work in this plan.
- TLS verification is always on; the only escape hatch is a plain-HTTP toggle (`use_ssl=false`). No skip-verify option.
- Path-style addressing defaults on for custom endpoints and off for `*.amazonaws.com`.
- The user creates the bucket; the app/server never creates it. App code must never call `MakeBucket` (only test fixtures may).
- `SetDriveS3` validates bucket existence and credentials **before** `im.SetDrive`; on failure the previous drive stays active.
- `Upload` stores the original photo time as user metadata key `taken-at` (RFC3339, UTC).
- Object key layout is exactly what `ImgManager` passes (`YYYY/MM/DD/...`, `.thumbnail/...`); keys use `/` and never start with `/`.
- Credentials stay plain text in `SharedPreferences` (keys `s3_endpoint`, `s3_region`, `s3_bucket`, `s3_access_key`, `s3_secret_key`, `s3_root_prefix`, `s3_use_ssl`, `s3_path_style`).
- App is English-only: new strings go in `lib/l10n/app_en.arb` only; no Chinese strings.
- Go: follow the existing `New*Drive` + `server/api/<name>.go` pattern; shared tests live in `server/drive/drive_test.go`.

## Review Focus

1. Endpoint typed as `https://s3.example.com/` or with a port / trailing slash. Expect scheme stripped, TLS set from the scheme. (Task 1)
2. Root prefix empty, `/photos`, `photos/`, `/a//b/`. Expect clean keys: no leading `/`, no `//`. (Task 1)
3. Photo names with spaces, `+`, `#`, `()` and non-ASCII (`IMG 0001 (1).jpg`, `日本.jpg`). Expect upload, download, list and delete round-trip exactly. (Task 2)
4. A video larger than the multipart threshold (17 MiB) uploaded, then read with an offset in the middle. Expect identical bytes. (Task 2)
5. Wrong credentials, missing bucket or unreachable endpoint at setup. Expect `success=false`, a readable message, previous drive untouched. (Task 3)
6. `Range` on a directory that does not exist. Expect no error and zero entries, not a failure. (Task 2)

- [ ] **Step 4: Implement `S3` in `s3.go`**, behaviors fixed by the shared suite and spec:
  - `Upload` streams with `PutObject` and the given size; sets `UserMetadata{"taken-at": lastModified.UTC().Format(time.RFC3339)}`; closes the reader.
  - `Download` stats first (error if missing) and returns the full object size. `DownloadWithOffset` stats first, **returns an error when `offset > size`** (the shared suite requires it; `GetObject` alone only fails on first read), returns an empty reader when `offset == size`, and otherwise ranged-reads from `offset` while still returning the full object size.
  - `IsExist` returns `(false, nil)` for not-found (error code `NoSuchKey` / HTTP 404), real errors otherwise. `Delete` of a missing key is not an error.
  - `Range(dir, deal)` lists non-recursively with prefix `objectKey(root, dir) + "/"` (empty prefix for root). Common prefixes become `fs.FileInfo` with `IsDir()==true`, zero `ModTime`, name without trailing `/`; objects become files with `LastModified` as `ModTime`. Skip zero-length "folder marker" keys ending in `/`. Files sorted newest first (existing convention); directories come after. Stop when `deal` returns false. A missing directory yields no entries and no error.
  - `Close` is a no-op returning nil. `PathStyle` picks `minio.BucketLookupPath`, otherwise `BucketLookupAuto`.
- [ ] **Step 5: Re-run the S3 suite from Step 3.** Expected: all subtests PASS.
- [ ] **Step 6: Add edge tests to `drive_test.go`** (run for S3 only, using the S3 case's drive):

- **Spec coverage:** drive methods and ranged reads (T2); metadata (T2 step 7); validation before activation, never creating the bucket (T3, constraints); TLS and path-style defaults (T1 endpoint, T4 helper); form, prefs, selector, background sync (T4); MinIO tests (T2); docs and README bucket note (T5); AAR size (T6); English-only strings (T4). - **Spec deviation (my call):** `NewS3Drive` takes a `Config` struct instead of eight positional arguments, which the spec only sketched.
- **Type consistency:** `Config`, `NewS3Drive`, `Check`, `ParseEndpoint`, `objectKey`, `SetDriveS3`, `Drive.s3`, `S3Form`, `defaultPathStyleFor`, `InitS3` are named identically everywhere they appear.
- **Known risks:** `make protobuf` may produce noisy diffs with plugin versions that differ from the committed ones; the MinIO image health check is not relied on; 14 Flutter tests already fail on `master` and are not in scope.
